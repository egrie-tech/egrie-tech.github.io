Self-hosting

Run the sync server yourself

The Android app is fully local without a server. A server only adds optional two-way encrypted sync and the audio-extraction endpoint — and it is plain Python with no Docker requirement, so a $5 VPS, a Raspberry Pi, or a box in your closet all work.

1. What the server is for

The supplied service provides three things: accounts and sessions, an end-to-end-encrypted sync log with encrypted checkpoints, and an optional audio-only YouTube extraction endpoint. Out of the box the app uses the operator's public instance at https://soundtrail.duckdns.org; running your own replaces that single URL and nothing else in your workflow changes.

The app encrypts each entity event and checkpoint on-device with AES-256-GCM before upload, and merges changes deterministically with a last-write-wins clock and a device-id tie-breaker, so the server is a durable relay rather than a content store. Pins, playlists, playlist songs, and automations sync both ways, including edits and deletions.

2. What the server can and cannot see

Visible to the serverNot visible to the server
Account email address, salted password hash, session tokens and expiry, request timing, source IP in proxy/server logs.Pin titles, notes, coordinates, playlist contents, song links, automation rules — all of it arrives as ciphertext.
Event IDs and sequences, ciphertext sizes, and per-account sync volume.The 256-bit recovery key, which never leaves the device.
For an extraction request: the single YouTube video ID you submit, plus the temporary audio file while it is served.Local audio files, imported music, and provider credentials, which are excluded from sync entirely.

End-to-end encryption of library content does not hide your account email, IP address, or traffic metadata. If you host the service for other people, those are the things they are trusting you with — along with whatever your reverse proxy logs.

3. Install natively

Python 3.10 or newer, on Linux, macOS, Windows, or BSD, on x86-64, ARM64, or other CPUs. FFmpeg and a JS runtime are needed only for the extraction endpoint.

  1. Clone the repository

    git clone https://github.com/mob5824m-wq/SoundTrail.git
cd SoundTrail/server

  2. Start it

    run.py creates a private .venv, installs the pinned dependencies, and starts the API. Use python3 run.py --setup to prepare without starting, and python3 run.py --test to run the API test suite.

    python3 run.py            # Windows: py -3 run.py

  3. Optional: extraction only

    Install FFmpeg on PATH. requirements.txt pins yt-dlp (pure Python); requirements-js.txt pins deno as a JavaScript runtime for YouTube's challenge solver, and Deno publishes wheels for only some platforms — elsewhere run.py skips it and uses Deno or Node from PATH. Update those pins deliberately and re-test extraction afterwards, because it breaks when YouTube changes.

The SQLite database is created at server/data/soundtrail.sqlite3. Configuration is three environment variables: PORT (default 8080), SOUNDTRAIL_HOST (default 127.0.0.1), and SOUNDTRAIL_DB for a different disk. Keep the loopback default.

4. Put TLS in front of it

The app expects an https:// URL (a bare host is upgraded to HTTPS), so a certificate is not optional. Caddy automates it: point DNS at the machine, then use server/Caddyfile.example, which is essentially:

sync.example.net {
    encode zstd gzip
    reverse_proxy 127.0.0.1:8080
}

Do not expose port 8080 directly. Configure the proxy to overwrite or sanitize client-supplied X-Forwarded-For before passing it upstream — the server trusts that header only when its direct peer is private or loopback, which is what makes per-IP limits meaningful. Keep your own request-body and rate limits at the proxy too, especially with multiple workers: the in-process limits reset on restart and apply per instance.

5. Run as a service, and back it up

Run it as a dedicated unprivileged user under your service manager. A systemd unit is the short version of what the repository documents:

[Service]
User=soundtrail
WorkingDirectory=/opt/soundtrail/server
Environment=SOUNDTRAIL_HOST=127.0.0.1
Environment=PORT=8080
Environment=SOUNDTRAIL_DB=/var/lib/soundtrail/soundtrail.sqlite3
ExecStart=/usr/bin/python3 /opt/soundtrail/server/run.py
Restart=on-failure

On macOS use launchd, on Windows Task Scheduler or a wrapper such as NSSM, with the working directory set to server. /health reports liveness only.

Back up the whole data folder with the service stopped, so you archive the database and its WAL side-files together, and test a restore from the archive:

mkdir -p backups && chmod 700 backups
tar -czf backups/soundtrail-data.tar.gz -C . data

This is the one operation with no undo: if the database is lost, only a backup restores the encrypted event log and checkpoints, and users cannot rebuild it from their devices' history. There is no server-side key or password reset that substitutes for it. Keep an off-host copy. The extraction endpoint also needs outbound network access to YouTube and enough free temporary disk for up to two concurrent 250 MiB downloads plus working files.

6. Limits, quotas, and the API surface

The database enforces a 64 MiB per-account quota for encrypted events and checkpoints, and snapshots are capped at 8 MiB. After a sync, event rows are pruned into the client's encrypted checkpoint and retry-receipt metadata goes with them, so an old delivery ID may be accepted again later — harmless because entity clocks and tombstones make duplicate old versions a no-op. Passwords are per-account salted scrypt hashes; session tokens are random, expire after 30 days, and are stored only as SHA-256 hashes.

There is deliberately no email verification, no password reset, and no key recovery endpoint. Extraction accepts exactly one YouTube video ID; playlists and general video downloads are not supported, and authorized: true is the caller's rights assertion, which the server cannot verify.

7. Point the app at your server

  1. Replace the URL

    In Soundtrail, open Connect → Cloud sync, put your public https:// URL in the Sync server URL field, and tap Create account and recovery key. A Use public server button resets the field to the default instance if you change your mind.

  2. Save the recovery key

    It is generated on the device and is the only way to decrypt your library on another one. A signed-in device can reveal it again; a new device needs the key itself, and uninstalling removes the local copy.

  3. Then add the second device

    Enter the same server URL, sign in, and enter the saved key. Automatic sync is off by default; Sync automatically when Soundtrail opens runs a sync at launch, which needs a signed-in account and this device's stored key. Retry sync re-runs the same merge after a failure, and Connect shows pending local changes.

8. If other people use your instance, you are the operator

Hosting Soundtrail code does not make the project maintainer the operator of your server. You become responsible for its deployment, updates, HTTPS, access controls, storage, logs, backups, and any privacy or legal obligations to your users — including publishing your own disclosure of what you retain and for how long, honouring deletion and access requests, and deciding how a lost password or a misuse report is handled.
